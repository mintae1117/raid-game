# 누나 레이드 (Nuna Raid) — 설계 문서

작성 2026-10-30. 발주자: 리포 소유자. 승인된 대화 내용을 바탕으로 정리했고, "(빌더 결정)"으로 표시한 항목은 구현자가 정한다.

## 1. 의도와 이유

친구 네 명이 각자 자기 컴퓨터에서 URL 하나로 접속해, 1인칭 시점으로 거대 돼지괴물 **"누나"**를 함께 잡는 협동 보스전 웹게임. 마인크래프트의 블록 세계·조작 느낌을 참고하되 똑같을 필요는 없다. 한 판 10분 안팎, 설치 없이 브라우저만 있으면 된다.

## 2. 목표 / 비목표 / 안티목표

**목표**
- 브라우저(데스크톱)에서 설치 없이 접속, 최대 4명 동시 플레이
- 1인칭 조작(포인터 락 마우스 시점, WASD 이동, 스페이스 점프, 좌클릭 공격)
- 기본 무기 + 맵에 랜덤 스폰되는 무기 파밍
- 1인당 목숨 3개, 섬 **가장자리 낙사** 존재, 누나의 공격에 **밀려나** 낙사할 수 있음
- 난이도 선택(쉬움/보통/어려움) + 인원수에 따른 자동 보정
- 승리/패배 화면과 다시 하기
- 인터넷 어디서든 접속: 호스트 컴퓨터에서 서버를 켜고 Cloudflare 임시 터널(quick tunnel)로 공개 URL을 받아 공유

**비목표**
- 계정, 저장, 랭킹, 매치메이킹(방은 서버당 하나)
- 모바일·터치 지원, 음성 채팅, 외부 3D 에셋·텍스처 파일, 정교한 물리 엔진
- 상시 배포(Cloudflare Workers 등)는 이번 범위 밖. 나중에 옮길 수 있게 서버 로직을 전송 계층과 분리해 둔다(빌더 결정 범위 안에서).

**안티목표(이러면 실패)**
- 플레이어마다 누나 체력·위치가 다르게 보이는 것 → 보스·무기·피격은 **서버 권위**
- 랙 때문에 억울하게 낙사하는 것 → 내 이동은 **클라이언트 권위**(즉시 반응), 서버는 속도 상한만 검증
- 난이도가 "넷이서 1분 컷" 또는 "절대 못 잡음"이 되는 것 → 보통 난이도 4인 기준 5~8분 클리어, 한두 명 목숨 소모를 목표로 튜닝

## 3. 제약

- Node 22, 의존성은 `three`, `ws`, `cloudflared`(npm 패키지, 바이너리 자동 다운로드) 정도로 최소화. 번들러 없이 ESM + importmap, three는 `node_modules`에서 정적 서빙.
- 브라우저: 최신 Chrome/Edge/Safari, Pointer Lock API 필요.
- 네트워크: WebSocket, JSON 메시지. 서버 틱 20Hz, 클라이언트 입력 보고 20Hz.
- 서버 하나 = 방 하나, 최대 4명(5번째 접속은 거부 메시지). 게임 중 **새** 입장자는 관전(다음 판 참여).
- 재접속: 터널 특성상 끊김이 잦으므로, 클라이언트는 세션 토큰을 localStorage에 두고 끊기면 자동 재접속한다. **60초 안에 돌아오면 같은 플레이어로 복귀**(목숨·무기·기여도 유지). 끊긴 동안 그 플레이어는 투명·무적·어그로 제외, 생존자 수에서도 제외된다. 60초가 지나면 탈락 처리(목숨 0과 동일, 패배 판정은 남은 사람 기준). 누나 HP(인원 계수)는 시작 시 고정.
- 실행: `npm install` → `npm start`(http://localhost:3000) → `npm run tunnel`(공개 URL 출력). `PORT` 환경변수 지원. README에 세 줄로 적는다.

## 4. 게임 규칙 (결정됨)

### 4.1 로비
- 접속 → 닉네임 입력(2~12자) → 로비. 첫 입장자가 호스트, 호스트가 나가면 다음 사람이 호스트.
- 호스트가 난이도(쉬움/보통/어려움, 기본 보통)를 고르고 "시작"을 누른다. 1명이어도 시작 가능.
- 로비 화면에 참가자 목록, 난이도, 조작법, 공개 URL 복사 버튼(서버가 터널 URL을 알면 표시, 모르면 현재 주소).

### 4.2 맵 — 이름 **낙성대동굴**
- 맵 이름은 "낙성대동굴". 로비의 맵 표시, 게임 시작 연출("낙성대동굴에 입장"), 결과 화면에 이름을 쓴다. 이름은 동굴이지만 지형은 아래의 공중 섬 그대로다(동굴 분위기를 낼지는 빌더 결정: 어두운 하늘·바위색 블록 정도).
- 48×48 블록(1블록 = 1m)의 단일 섬, 높이 1의 평지. 구멍은 없다. 장식으로 통과 불가 블록(나무·바위) 8~12개를 가장자리 쪽에 둔다.
- 섬 밖은 허공. 플레이어 y < −10 → 낙사.
- 스폰 지점: 섬 중앙 반경 6m 안 4곳. 누나 초기 위치: 중앙에서 15m 떨어진 곳.

### 4.3 플레이어
- HP 100, 목숨 3. 이동 5m/s, 점프 높이 1.2블록, 달리기 없음. 플레이어끼리 충돌 없음.
- 사망(HP 0 또는 낙사) → 3초 뒤 스폰 지점에서 부활(HP 100, 기본 무기로 초기화), 목숨 −1. 목숨 0 → 관전 시점(자유 카메라).
- 전원 목숨 0 → 패배.

### 4.4 누나 (보스)
- 각진 돼지, 크기 약 6×4×5 블록. 머리 위 이름 "누나", 화면 상단에 체력 바.
- 몸체는 플레이어를 **막는다**(움직이는 AABB). 단, 누나가 걸어오며 미는 힘은 아주 약하게(플레이어를 옆으로 밀어내는 정도)로 두어 걷기만으로는 낙사가 나지 않게 한다. 밀어내기 낙사는 돌진·땅찍기 넉백만 담당. 물기 사거리 2.5m는 **몸체 표면 기준**.
- 체력 = 난이도 기본값 × 인원 계수. 보통 기본 **7,000**(초안 1,200은 무기 피해와 안 맞아 상향). 인원 계수 1인 1.0 / 2인 1.7 / 3인 2.3 / 4인 2.8. 인원 계수는 **시작 시점 인원으로 고정**.
- 튜닝 기준: "느낌"으로 지키는 값은 공격 속도(근접 0.5초)와 무기 피해 숫자, 돌려도 되는 값은 누나 HP와 쿨타임. 목표 클리어 시간: 보통 4인 5~8분, 1인 4~6분. 봇 시뮬로 HP를 맞춘다.
- 이동 기본 2.5m/s.
- 행동(서버 AI, 상태 기계):
  1. **추격**: 어그로 대상에게 다가감. 2.5m 안이면 **물기**(10 dmg, 넉백 없음, 쿨 1.5초).
  2. **돌진**: 1.2초 예고(몸 낮춤 + "누나가 돌진 준비!" 텍스트) → 15m/s로 직선 8m. 맞으면 25 dmg + **돌진 방향으로 6m 넉백**.
  3. **땅 찍기**: 1초 예고 → 반경 6m 광역 30 dmg + **누나 중심 바깥 방향 5m 넉백**. 예고 중 점프해 공중에 있으면 피해·넉백 없음.
  4. **포효**(2단계부터): 반경 10m 플레이어 2초간 이동 속도 50%.
- 단계: HP 100~60% 1단계(돌진/땅찍기 쿨 8초), 60~30% 2단계(쿨 6초, 속도 +20%, 포효 추가), 30~0% 3단계(쿨 4초, 속도 +40%, 돌진 2연속).
- 어그로: 최근 5초 누적 피해 1위 60%, 가장 가까운 플레이어 40% 확률로 3초마다 재선택.
- 넉백 세기 기준: 섬 중앙 반경 12m 안에서 맞으면 절대 가장자리까지 밀리지 않고, 가장자리 6m 안쪽에서 맞으면 떨어질 수 있다. 넉백은 수평 임펄스 + 약간의 상승, 0.4초간 감쇠.

### 4.5 무기
| 무기 | 종류 | 피해 | 사거리/속도 | 쿨 | 비고 |
|---|---|---|---|---|---|
| 나무 검 | 기본 근접 | 12 | 3m | 0.5초 | 시작·부활 시 지급 |
| 돌검 | 근접 | 18 | 3m | 0.5초 | |
| 철검 | 근접 | 26 | 3m | 0.5초 | |
| 다이아 검 | 근접 | 38 | 3m | 0.5초 | |
| 활 | 원거리 | 20 | 화살 30m/s | 0.8초 | 30발, 소진 시 나무 검으로 |
| TNT | 투척 광역 | 누나 60 / 플레이어 20+넉백 | 포물선 투척, 2초 후 반경 4m | 1초 | 3개, 자해 가능 |

- 스폰: 맵에 동시 최대 5개. 10초마다 빈 자리에 하나 추가(빈 자리 없으면 대기). 가중치 돌검 35 · 철검 25 · 활 20 · 다이아 10 · TNT 10. 스폰 위치는 섬 중앙 반경 8m 밖, 가장자리 3m 안쪽.
- 슬롯: 플레이어는 **근접 1칸 + 특수 1칸**(활·TNT)을 가진다. 숫자키 1/2 또는 마우스 휠로 전환. HUD에 두 칸 표시.
- 줍기: 1.5m 안에 들어가면 자동. 근접 무기는 들고 있는 것보다 등급이 높을 때만 교체(낮으면 그대로 두고 지나감). 특수 무기는 특수 칸에 들어가며 같은 종류면 탄약만 보충, 다른 종류면 교체. 교체된 무기는 사라진다(드롭 없음). 부활 시 두 칸 모두 초기화(나무 검만).
- 근접 판정: 클라이언트가 공격 입력과 조준 방향을 보내면 서버가 플레이어 위치·시선 ±30°·3m 안에 누나 바운딩 박스가 있는지로 판정.

### 4.7 승패와 결과
- 누나 HP 0 → 쓰러지는 연출 3초 → 결과 화면: 걸린 시간, 플레이어별 피해 기여(%), 사망 수, MVP.
- 패배 → 결과 화면(같은 항목 + "누나 남은 체력").
- 호스트 "다시 하기" → 로비(난이도 유지).

### 4.8 HUD와 조작
- 십자선, 내 HP 바, 목숨(하트 3), 현재 무기와 탄약, 누나 체력 바(상단), 팀원 이름·HP 목록(좌상단), 공격 예고 텍스트(중앙 상단), 이벤트 토스트(줍기·사망·단계 전환).
- 클릭으로 포인터 락, WASD, 스페이스 점프, 좌클릭 공격/발사/투척, Esc 락 해제. 마우스 감도 슬라이더(로비).

## 5. 아키텍처 (빌더가 정한 방식, 바꿔도 됨)

- `server/`: Node + `ws`. 상태 `lobby | playing | ended`. 20Hz 틱에서 누나 AI, 투사체(화살·TNT), 무기 스폰, 피격·넉백 계산 → 스냅샷 브로드캐스트. 게임 규칙은 `ws`에 의존하지 않는 순수 모듈로 두어 단위 테스트와 나중의 배포 이전이 쉽게.
- 이동은 클라이언트 권위: 클라이언트가 위치·시선을 20Hz로 보고, 서버는 틱당 이동량 상한만 검사. 낙사는 클라이언트가 `fell`을 보고하면 서버가 처리. 넉백은 서버가 임펄스 벡터를 해당 클라이언트에 보내고 클라이언트가 자기 물리에 적용.
- 메시지(JSON). 클라이언트→서버: `join{name}`, `difficulty{level}`, `start`, `input{pos,yaw,pitch,t}`, `attack{dir}`, `fell`, `restart`. 서버→클라이언트: `lobby{players,hostId,difficulty,publicUrl}`, `start{seed,map}`, `snap{players[],boss{pos,yaw,hp,maxHp,state,phase,telegraph},projectiles[],pickups[]}`, `event{type,...}`(hit, death, pickup, phase, telegraph, win, lose), `knock{impulse}`.
- `client/`: `index.html`(importmap, HUD DOM), `main.js`(접속·로비), `game.js`(Three.js 장면: InstancedMesh 블록 섬, 플레이어 컨트롤러와 간단 물리, 누나 모델과 애니메이션, 무기 모델, 투사체, 카메라 흔들림), `net.js`.
- 아트: 모든 모델은 BoxGeometry 조합, 색·무늬는 CanvasTexture로 생성(체커·픽셀 느낌). 하늘은 그라데이션, DirectionalLight + 저해상도 그림자. 성능 목표: 보통 노트북 60fps, 블록 ~2,500개 인스턴싱.
- 사운드: Web Audio로 합성한 간단 효과음(공격·피격·예고·사망) (빌더 결정, 없어도 됨).

## 6. 테스트와 튜닝

- 서버 순수 모듈에 `node:test` 단위 테스트: 넉백 벡터·세기, 근접 피격 판정, 단계 전환, 무기 스폰 가중·최대 개수, 승패 전이, 인원 계수.
- 봇 시뮬레이션 스크립트: 서버 모듈에 단순 봇 4명(누나 주위를 돌며 공격, 예고 시 뒤로 빠짐)을 붙여 보통 난이도 클리어 시간이 5~8분 범위인지 확인하고 수치를 맞춘다.
- 수동: 브라우저 창 2개로 로컬 플레이, 터널로 외부(폰 핫스팟 등) 접속 1회 확인.

## 7. 검토 후 추가 결정 (2026-10-30)

검토자 질문 4건은 모두 빌더(구현자)가 정했다: 누나 HP 상향과 튜닝 기준(4.4), 몸체 충돌과 물기 기준점(4.4), 무기 2슬롯과 줍기 규칙(4.5), 재접속 복귀 60초(3장). 그 외 터널 URL 전달 방법, 넉백 중 속도 상한 예외, 화살 아군 피해 없음, 돌진/땅찍기 선택 규칙도 빌더 결정.

## 8. 빌더에게 맡기는 것

모델 비율·색, 애니메이션 디테일, 효과음 유무, 결과 화면 디자인, 코드 파일 구조, 테스트 세부, 텍스트 문구.
